# 二次开发与大量改动说明

## 定位与维护者署名

**AiteEcho（艾特回声）由ilovvveu主导持续开发和维护，是在上游qq-ai-bot基础上进行大量修改、功能扩展及架构/安全/部署适配后形成的独立维护版本。** 它不是只替换名称或捐款入口的原样镜像，也不将上游已有代码、协议或第三方能力宣称为本人从零原创。

原项目作者、仓库来源、取得的本地基线提交及许可见[NOTICE](../NOTICE)。原版权和MIT全文保留；维护版本的修改版权一并列在LICENSE。维护者主导产品需求、功能整合、二次开发和维护，不对代码由何种辅助工具产生作不实手工原创声明。

## 与所取得上游基线的主要区别

本地可追溯基线为1c940a0。下表区分沿用的基础与后续工作，不按行数百分比推断权属，也不声称这些能力全由某个人独立发明。

| 领域 | 沿用基础 | 本维护版本的新增、重构或显著改造 |
| --- | --- | --- |
| QQ接入与会话 | OneBot消息通道、ACP桥接、命令及session store | 以独立Responses API作为推荐部署主线，不依赖桌面Codex；保留ACP兼容及共享提示结构 |
| 模型请求可靠性 | 基础agent请求与状态观察 | 文字/字节输入预算、完整响应/最终答案校验、分阶段截止、提交后不明结果防重放、显式回退及提供方参数兼容 |
| 历史与上下文 | 会话持久化与控制 | 100轮/时间/大小有界修剪、最多6轮/3000字符的direct短历史、按人/话题筛选、显式/context、旧图片与reasoning不重放 |
| 图片、引用与文件 | 消息/图片传递基础 | QQ CDN及私网/跳转校验、缓存白名单、同会话图片流证明、一层引用、macOS Vision OCR、只读文档有界提取 |
| 群聊策略 | 基础群/用户过滤 | 主人/实际QQ管理/普通/特殊成员分层、逐人限频/持久化规则、公开群管理指令边界及有界按人发言分析 |
| 风格与表达 | system prompt和会话控制 | 空白通用默认、多套自建预设、主人/style、全局规则热加载、来源展示与旧语气隔离；不固定个人角色 |
| 语音输出 | 无本版本TTS/SILK链路 | 显式命令、独立TTS、角色语音额度与普通额度联动、短答纯语音/失败文字回退、本地SILK转码和用量保护 |
| 诊断与记录 | 基础日志/指标 | 分环节correlationId、安全错误分类、独立可选真实@问答存档，明确ACK、未确认、失败与撤回边界 |
| 发布与运维 | 原仓库构建/部署和macOS工具 | 管理鉴权与回环默认、默认关闭聊天/显式主人、移除个人配置、构建/包/隐私扫描、工具进程归属/配置保护、CI烟测与文档重整 |

实际源码入口包括src/agents/direct、src/core/bounded-context.ts、document-reader.ts、local-ocr.ts、group-access.ts、group-history.ts、reply-style.ts、reply-rules.ts、voice.ts及mention-journal.ts等。上游也已有会话控制、存储、基础图片通道、进度和指标等能力，不能把这些整体改称全新发明。具体功能、默认开关及不支持项以[功能说明](features.md)和源码为准。

## 名称与兼容性

AiteEcho取“@触发、回声回应”的含义。项目不与某一家模型或桌面应用绑定；中文名“艾特回声”是产品描述，不是官方授权、商标注册或全网唯一名称的保证。本轮未创建远端仓库、注册包名或发布镜像。

既有本机工程/运行目录、launchd标签不因品牌改名自动迁移或重启。历史内部名QQ-Codex、部分QQ_CODEX_*变量、qq-ai-bot脚本/存储前缀和qq_ai_bot指标保留兼容，不表示必须接入Codex。新包名/显示名及预定仓库元数据使用AiteEcho/aite-echo，不能直接用品牌替换所有持久化标识导致数据丢失。
